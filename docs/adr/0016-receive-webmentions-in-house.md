# 0016. Webmention の受信を自前で実装し、検証は非同期に回す

- Status: Accepted
- Date: 2026-08-12
- Deciders: @yantene

## Context / 背景

IndieWeb の Webmention に対応し、記事への返信・いいね・リポスト・言及を集める。
「発信のすべてを集約するハブ」という趣旨に合う。

Webmention の受信には仕様上の要求がいくつかある。

- 受け口は `application/x-www-form-urlencoded` の `source` / `target` を受ける
- **source が本当に target をリンクしているかを、こちらで取りに行って確かめる**。
  これを省くと、誰でも好きな URL を source と称して投げるだけで、こちらの記事に
  他人の名前で行を作れてしまう
- 再送は更新として扱う。リンクが消えたら削除として扱う

一方で Cloudflare Workers には CPU 時間の制約があり、外部サイトの取得を送り手の応答の中で
待つと、相手が遅いだけでこちらが落ちる。取りに行く先はこちらが選べない任意の URL でもある。

## 検討した選択肢

### 受け口をどこに置くか

- **案 A: webmention.io (ホスト型)** — `<link rel="webmention" href="https://webmention.io/...">`
  を出し、受信と検証は外部サービスに任せ、表示時に API で引く。
  - Pros: 実装がほぼ要らない。スパム対策も向こうが持つ。
  - Cons: 受け取った反応がこちらのデータではなくなる。サービスが止まれば読めない。
    「作る」ことそのものがこのサイトの趣旨なので、要になる部分を外に置く動機が薄い。
- **案 B: 自前で受けて D1 に持つ** — `POST /webmention` を実装する。
  - Pros: 受け取った反応がこちらのものになる。表示も保存も自分で決められる。
  - Cons: 検証・スパム対策・非同期処理を自分で書く。

### 検証をいつやるか

- **案 C: 同期 (応答を返す前に source を取りに行く)** — 検証結果を HTTP の status で返せる。
  - Pros: 送り手にその場で結果が返る。
  - Cons: 相手のサーバーの遅さがそのままこちらの応答時間になる。遅い相手 1 件で
    Workers の実行時間を使い切る。仕様も同期の完了を求めていない。
- **案 D: 非同期 (`ExecutionContext.waitUntil`)** — 形式の検証だけして 202 を返し、取得は後回し。
  - Pros: 応答が相手の速度に左右されない。仕様どおり (202 Accepted)。
  - Cons: 送り手には「受け付けた」までしか返らない。結果はこちらのログにしか出ない。

### microformats2 をどう読むか

- **案 E: `microformats-parser` を使う** — parse5 の上に載った mf2 パーサ。
  - Pros: h-entry / h-card の入れ子、相対 URL の解決、`e-content` の平文化まで面倒を見る。
    依存は parse5 だけで、Node 固有の API を使わないので Workers で動く。
  - Cons: バンドルが増える (parse5 込みで数百 KB。Worker 側にだけ載る)。
- **案 F: 最小限の抽出を自前で書く** — 正規表現でクラス名と属性を拾う。
  - Pros: 依存が増えない。
  - Cons: mf2 は「入れ子の h-card」「`u-*` は href、`p-*` はテキスト」「暗黙の name/url/photo」
    といった規則の塊で、正規表現で近似すると読み違えが常態化する。相手の書き方は選べない。

## 決定

**案 B・案 D・案 E を採る。**

`POST /webmention` を自前で実装し、D1 の `webmentions` テーブルに持つ。同期段でやるのは
送り手に直してもらえる形式の検証だけで、いずれも 400 (RFC 9457 Problem Details) を返す。

- `source` / `target` が無い・URL でない・http/https でない
- `source` と `target` が同じ
- `target` がこのサイトのノート URL (`/notes/<slug>`) でない、または該当ノートが無い
- `source` がこのサイト自身 (self-mention は受けない)

ここを通れば 202 Accepted を返し、そこから先は `waitUntil` に逃がす。非同期段では source を
取りに行き、**target への実リンクが確認できたものだけ**を保存する。リンクが見当たらなければ
保存済みの行を落とす (再送で更新される仕様の裏返しで、リンクを消したら取り消しになる)。
404 / 410 も同じく削除として扱う。

**外部サイトの取得と mf2 のパースは fail-loud にしない。** このサイトの既定は「静かに劣化
させない」だが、相手が落ちている・遅い・HTML を返さないのはこちらの不具合ではなく、投げ
上げても直せるものが無い。理由をログに残して保存を見送るだけにする。ただし**取れなかった
ときに既存の行を消さない**。一時的な障害で過去の返信まで失わないため、削除は「取れたうえで
リンクが無い」ことを確かめてから行う。

取りに行く先は任意の URL なので、**タイムアウト (10 秒) と本文サイズの上限 (1 MiB) を課す**。
上限を超えたら途中まで読んだ HTML は使わず諦める。切れた位置より後ろにリンクがあっただけの
相手を「リンクしていない」と誤判定するため。受け取る側の本文にも上限 (4 KiB) を置く。
中身は URL 2 本だけで、誰でも叩ける口だから。

**転送を追った先が source と別のホストなら保存しない。** 追い先の文書は source の文書では
ないので、名乗りと中身が食い違ったまま保存すると次の二つを許してしまう。

- **自分のページを読んで自分で頷く**: 記事ページは自分自身への canonical リンクを出して
  いるので、こちらへ転送するだけでリンクの検証を通る。第三者サイトのオープンリダイレクタを
  1 つ見つければ、その名前で好きな記事に行を作れる
- **他人の返信を横取りする**: 誰かの本物の返信ページへ転送すれば、その人の名前と本文を、
  こちらの選んだ source の行として保存させられる

判定は origin ではなくホスト名で行う。スキームだけの転送 (http → https) は素通しさせたい
ため。別ホストへの転送 (短縮 URL・www の付け外し) は通らなくなるが、送り手は記事そのものの
URL を投げればよい。

**保存する著者名と本文は、VO の生成時点で HTML を落としたテキストにし、長さの上限で切る**
(著者名 100 文字 / 本文 1000 文字)。外部から届いた文字列をそのまま画面に出す前提を作らない
ためと、1 通で容量を好きなだけ食われないため。実体参照はタグを落とした**あと**に戻す
(順序が逆だと `&lt;script&gt;` が本物のタグに化ける)。均すのは**書くときだけ**で、読み戻す
ときは掛け直さない。均した結果には `<` が文字として残りうるので、掛け直すとそれをタグの
始まりと見なして落とし、読んだ値が保存した値と変わる。

そのため列に入っているのは「タグの無いテキスト」であって「`<` を含まない文字列」ではない。
**表示は必ずエスケープされる経路 (React の子要素) で出す**こと。

source の URL は**素片 (`#...`) を落として**保存する。素片はサーバーに送られないので、
`#1` から `#9999` まで並べても相手が返す文書は同じ 1 つ。残すと「別の source」として
何行でも積めてしまう (source は行の一意キーの一部)。

リンクの照合は「タグの中の `href` / `src`」だけを見る。本文に URL の字面を書いただけの
ページを「リンクしている」と読むと、検証の意味が無くなる。

`<link rel="webmention">` は**記事ページだけ**が出す。受け取れるのはノート宛だけなので、
トップや一覧で広告しても送り手を無駄に 400 へ歩かせるだけになる。

staging では BASIC 認証の内側に居るため外から届かないが、それでよい。認証を回避する例外は
開けない (staging に外部から届く必要は無く、穴の方が高くつく)。

## 帰結 / Consequences

- 良い面: 受け取った反応がこちらのデータとして D1 に残り、表示のしかたを自分で決められる。
  応答が相手のサーバーの速度に左右されない。mf2 の解釈をパーサに任せられるので、相手の
  書き方の幅に振り回されない。
- 悪い面・トレードオフ: 送り手には検証結果が返らない (202 までしか返さない)。Worker の
  バンドルが parse5 のぶん増える。別ホストへ転送する URL は受け取れない。スパム対策は
  「実リンクの確認 + 長さの上限 + 素片の正規化」までで、許可リストやレート制御はまだ無い
  (自分のサイト上に URL を並べれば、1 記事に何行でも積める余地は残っている)。
- 検証方法: `webmention.handler.test.ts` が同期段で断るものを網羅し、非同期段で
  「リンクしていなければ保存しない」「取りに行けなくても落ちない」「再送で増えない」
  「リンクが消えたら落とす」を固定する。`webmention-source-reader.test.ts` が
  「本文に書かれただけの URL を数えない」ことを、
  `webmention-verification.service.test.ts` が「自サイトや別ホストへ転送されたら
  保存しない」ことを固定する。
