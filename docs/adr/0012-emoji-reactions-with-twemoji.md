# 0012. ノートへのリアクションを一人 1 つに限り、意匠は Twemoji を self-host する

- Status: Accepted
- Date: 2026-08-12
- Deciders: @yantene

## Context / 背景

ノートに絵文字でリアクションできるようにする。基本は「いいね」で、ハートを押すとそれになる。
好きな絵文字を選びたい人はパレットから選ぶ。

読まれた回数からは「いま人気のノート」を出している (ADR 0011、domain/note-view/view-ranking)。
リアクションは読むより強い意思表示なので、この順位にも効かせたい。ただし読み手が自由に
押し引きできる値を順位に混ぜる以上、押し消しを繰り返して順位を動かせる余地を作らないこと。

意匠には Twemoji を使いたい。ただし Twitter 時代の `twitter/twemoji` はアーカイブされており、
どこを参照するかを決める必要がある。CSP は `font-src 'self'` / `img-src 'self' data:` で、
外部 CDN を読めない (ADR 0007)。

## 検討した選択肢

### 押せる数

- **案 A: 1 ノートにつき 1 人 1 つ** — 別の絵文字を押すと差し替わる。
  - Pros: セッションが持つのは「この記事に何を押したか」1 件で済む。スコアへの寄与も
    一人ぶんに揃う。
  - Cons: 「面白い」と「ためになった」を同時に伝えられない。
- **案 B: 複数可 (Slack や GitHub の形)** — 絵文字ごとに独立してトグルする。
  - Pros: 表現の幅が広い。
  - Cons: 一人で何個も押せるぶん、スコアへの寄与を別途頭打ちにする必要がある。セッションに
    持つ状態も集合になる。

### スコアの取り消し

- **案 C: 取り消してもスコアを減らさない** — 加算は初回だけに限り、以後は何をしても動かさない。
  - Pros: 減算の数値的な扱い (log-sub-exp) を持たなくてよい。
  - Cons: 押し消したのにスコアが残る。「加算済みか」をセッションに別途持つ必要があり、
    状態が増える。
- **案 D: 押したときに足した値をそのまま引く** — 押した日を覚えておき、同じ重みを引く。
  - Pros: 押す/消すが対称になる。繰り返しても元に戻るので、特別な歯止めが要らない。
  - Cons: 対数のまま引く計算 (log-sub-exp) と、引きすぎの防止が要る。

### Twemoji の配り方

- **案 E: SVG を自前でホストして `<img>` で出す** — 1902 個のファイルを置く。
  - Pros: 必要なものだけ読める。
  - Cons: パレットに全絵文字を並べると数千リクエストになる。
- **案 F: COLR フォントを self-host する** — 1 ファイルをフォントとして読み込む。
  - Pros: リクエストは 1 回。記事本文の絵文字も同じ意匠に揃う。`unicode-range` を付ければ
    日本語や英数字は既存フォントのまま残る。
  - Cons: 全絵文字ぶんの重さ (woff2 で 617KB) を一度に読む。

## 決定

**案 A・案 D・案 F を採る。**

1 ノートにつき 1 人 1 つ。押した人は読み手のセッション (KV) が持つ。ADR 0011 はこの用途を
見越してセッションを置いており、その上に乗せる。閲覧の記録と違い、リアクションは**日が
変わっても捨てない**。捨てると取り消しも差し替えもできなくなり、同じ人が何度でも押せる。

スコアはリアクション 1 つを**閲覧 5 回ぶん**の重みとして足す。対数で持っているので、
倍率は `log(5)` の加算で済む。取り消しでは、押した日から作った同じ重みを log-sub-exp で引く。
だからセッションは「いつ押したか」も持つ。今日の重みで引くと、日をまたいで押し消しするだけで
スコアを削れてしまう。

引くときは**下限としてその記事の出発点 (投稿日の重み) を渡す**。対数のまま足すと桁が離れた
小さいほうは丸めで消えるため、まだ一度も読まれていない古い記事では、リアクションを足した
時点で出発点が倍精度の外に落ちる (重みの差が 37 桁ぶんを超えると `exp` が 0 に潰れる)。
消えた値は引き戻せないので、下限を置かないと引ききったまま戻らない。実装中に実際に踏んだ。

**絵文字の差し替えではスコアを動かさない。** リアクションしている事実自体は続いているためで、
ここで今日の重みに付け替えると、押し直すだけでスコアを積める抜け道になる。

意匠は [jdecked/twemoji](https://github.com/jdecked/twemoji) を源とする COLR フォントを
self-host する。Twitter 時代のリポジトリはアーカイブされたが、当時の担当者たちが引き継いだ
このフォークが Unicode 17.0 / Emoji 17.0 に追随している。

受け入れる絵文字は生成した一覧に**完全一致**するものだけとし、肌の色・髪の色の派生は
一覧から除く (バリエーションは持たせない)。一覧はパレットが出す集合と同じものを使う。
サーバーとパレットで別々に持つと、片方だけを直せてしまう。

## 帰結 / Consequences

> **フォントの適用先は [ADR 0015](0015-twemoji-scoped-to-reaction-ui.md) で改めた。**
> ページ全体のフォントスタックに置くと、`unicode-range` に含まれる ASCII の数字を
> 巻き込んで本文の数字が消えるため、リアクションの UI にだけ当てる。以下の
> 「記事本文の絵文字も含めて意匠が揃う」は取り下げている。

- 良い面: 押す/消すが対称なので、順位を動かすために押し消しを繰り返しても意味がない。
  「加算済みか」のような追加の状態を持たずに済む。フォント 1 ファイルで、記事本文の絵文字も
  含めて意匠が揃う。
- 悪い面・トレードオフ: 一人 1 つなので複数の気持ちは伝えられない。押した記録が
  セッションに溜まり続ける (閲覧と違って捨てられない)。フォントの 617KB を読む。
- 検証方法: `view-ranking.test.ts` が押し消しの往復でスコアが戻ることを固定する
  (1000 回繰り返しても動かないこと、読まれていない古い記事でも出発点に戻ること)。
  `reaction.handler.test.ts` が API 越しに、差し替えでスコアが動かないこと・一覧に無い
  絵文字と肌の色付きが弾かれることを固定する。
