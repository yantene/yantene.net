# 0017. 本文と数式の字は Google Fonts から読み、CSP をその 2 ホストにだけ開く

- Status: Accepted
- Date: 2026-08-13
- Deciders: @yantene

## Context / 背景

字を読み手の環境任せにしていた。本文のフォントスタックはシステムの日本語フォントを並べた
ものなので、同じ記事が macOS ではヒラギノ、Windows では游ゴシック、Android では Noto で
出る。字面が変われば行の詰まりも変わり、意図した組みにならない。

数式はもっと悪い。本文の `$...$` は refresh のときに KaTeX の MathML 出力で組んで MDAST に
埋めており ([ADR 0013](0013-math-as-mathml-at-refresh-time.md))、描画側は MathML を出すだけ
なので、字は本文のスタックをそのまま継承する。つまり数式がゴシックで組まれる。

手元の Chrome で確かめたところ、これは字面の好みだけの話ではなかった。

| 指定                                  | 結果                                                   |
| ------------------------------------- | ------------------------------------------------------ |
| 本文のゴシックを継承 (それまでの状態) | サンセリフ。`Σ` `∫` は本文と同じ大きさのまま           |
| `serif`                               | セリフにはなるが `Σ` `∫` は小さいまま、添字も詰まる    |
| `"Noto Serif", serif`                 | **根号の上線が消える**                                 |
| STIX Two Math                         | `Σ` `∫` が大型演算子として組まれ、根号が式の丈に伸びる |

ブラウザが大型演算子を伸ばし、根号や括弧を式の丈に合わせるには、フォントが OpenType の
MATH テーブルを持っている必要がある。持たない本文用のセリフ体を名指しすると、組版に必要な
情報が無いまま描かれ、**上線が消えるといった形で静かに崩れる**。「セリフ体なら何でもよい」
ではない。

一方、CSP は `style-src 'self'` / `font-src 'self'` で外に閉じている
([ADR 0007](0007-strict-csp-outside-development.md))。外から字を読むには、この 2 つを
開ける必要がある。

## 検討した選択肢

- **案 A: 何もしない (システムのフォント任せ)**
  - Pros: 転送量ゼロ。CSP を触らない。
  - Cons: 字面が環境で変わる。数式は MATH テーブルを持つフォントに当たらない限り、
    大型演算子が小さいまま組まれる。
- **案 B: フォントを self-host する (`public/` に置き `font-src 'self'` のまま)**
  - Pros: CSP を一切緩めない。読み手の IP が第三者に渡らない。同一オリジンなので
    接続が増えない。Twemoji で前例がある ([ADR 0012](0012-emoji-reactions-with-twemoji.md))。
  - Cons: 日本語がこれに向かない。字ごとの分割配信を自前で用意する必要があり、
    やらなければ数 MB を丸ごと読ませることになる。分割を手で維持するのは現実的でない。
- **案 C: 数式だけ self-host し、本文はシステム任せのまま**
  - Pros: STIX Two Math は分割の要らない 394KB 一本で、数式のある記事しか取りに行かない。
    CSP を触らずに数式の組版だけ直る。
  - Cons: 本文の字面は揃わないままになる。
- **案 D: Google Fonts から読み、CSP をその 2 ホストにだけ開く (採用)**
  - Pros: 日本語の分割配信 (`unicode-range` で 249 チャンク) をそのまま使える。本文も数式も
    一度に揃う。開けるホストは名指しなので、他所からは読めないまま。
  - Cons: 読み手のリクエストが第三者 (Google) に渡る。転送量が増える。外部の可用性に
    依存する。CSP の外向きの口が 2 つ増える。

## 決定

案 D を採用する。本文に Noto Sans JP (400 / 700)、数式に STIX Two Math を当て、CSP の
`style-src` に `https://fonts.googleapis.com`、`font-src` に `https://fonts.gstatic.com` を
足す。

### ADR 0007 との関係

0007 が禁じているのは `'unsafe-inline'` を足すことで、必要なホストを名指しで並べることでは
ない。`frame-src` に `https://www.youtube-nocookie.com` を挙げて埋め込み動画を通しているのと
同じ形なので、0007 の決定は覆らない。**`'unsafe-inline'` は今後も足さない。**

### 転送量について

日本語は 249 チャンクに分かれているが、漢字が広く散るので 1 記事で 50〜92 チャンクを引く。
実際の記事で計測した転送量 (400 + 700 の両ウェイト)。

| 本文の長さ | チャンク | 転送量   |
| ---------- | -------- | -------- |
| 2,768 字   | 50       | 963 KB   |
| 3,751 字   | 74       | 1,387 KB |
| 5,228 字   | 92       | 1,817 KB |

軽くはない。**字面を揃えることを優先してこのコストを飲む、という判断である。**
STIX Two Math の 394KB は数式のある記事でしか要求が出ない (`@font-face` は使われて初めて
取りに行く)。

`display=swap` にしてあるので、届くまではシステムのフォントで出る。日本語は字幅が変わる
ため差し替わりが目に見えるが、字が出ないまま待たせるよりはよい。

### 数式のフォントスタックの書き方

```css
font-family: "STIX Two Math", math, serif;
```

**MATH テーブルを持たないフォントを間に挟まないこと。** `"Noto Serif", serif` のように
本文用のセリフ体を名指しすると、根号の上線が消える。

落とし先が `math` なのは、これが CSS Fonts 4 のジェネリックで、ブラウザが手元の数式
フォント (Cambria Math / STIX Two Math など) に解決するため。**`serif` に落としてはいけない。**
`serif` は本文用のセリフ体に解決されるので、上の表の 2 行目 (「セリフにはなるが `Σ` `∫` は
小さいまま」) にそのまま落ちる。`fonts.googleapis.com` へ届かなかったときは必ずこの経路を
通るので、ここの選択がそのまま「落ちているときの見え方」になる。

末尾の `serif` は `math` を知らない古いブラウザの受け皿。そこでは `math` は「math という
名前のフォント」と読まれ、見つからずに次へ落ちる (宣言ごと捨てられはしない)。

### ウェイトは 400 と 700 だけ読む

CSS には `font-weight: 500` / `600` を使っている箇所がある (インラインコード、
typography 既定の `a` / `strong` など)。**Noto Sans JP が当たると、これらは 400 / 700 に
丸められる** (CSS のフォントマッチングの規則で、500 は 400 へ、600 は 700 へ寄る)。
中間ウェイトを持つシステムフォントで出ていたときより、地の文との差が小さくなる。

500 を足せば解決するが、日本語のウェイトを 1 つ増やすことは転送量を 5 割増やすことでも
あるので、ここでは丸めを受け入れる。インラインコードは背景色、本文リンクは色が付いており、
太さ以外の手がかりが残る。

## 帰結 / Consequences

- 良い面: 本文の字面が環境によらず揃う。数式が MATH テーブルの上で組まれ、大型演算子と
  根号が式に追随する。日本語の分割配信を自前で持たずに済む。
- 悪い面・トレードオフ:
  - 記事を開くと 1〜1.8MB のフォントを取りに行く。
  - 読み手のリクエストが Google に渡る。self-host なら渡らなかった。
  - `fonts.googleapis.com` が落ちるとシステムのフォントのまま出る (`swap` なので字は出る)。
    数式もそのとき `math` ジェネリックに落ち、手元に数式フォントが無ければ大型演算子は
    小さいままになる。
  - `font-weight: 500` / `600` が 400 / 700 に丸まる (前節)。
  - CSP の外向きの口が 2 つ増えた。増やすときに歯止めが要る。
- 検証方法 / 今後の宣言:
  - `app/backend/csp.test.ts` が「`style-src` / `font-src` が Google Fonts の 2 ホストにだけ
    開いていること」「他の口は `'self'` のままであること」を固定する。**ディレクティブを
    丸ごと取り出して突き合わせる**こと。部分一致で見ると、後からホストを足しても
    素通りしてしまい歯止めにならない。
  - 外部リソースを足したので、**`pnpm run preview:staging` で CSP 下の実物を確認すること。**
    dev には CSP が付かないので確認にならない (ADR 0007)。
