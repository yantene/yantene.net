# 0049. 本文のリンクのプレビューは触ったときに取り、位置は CSS で決める

- Status: Accepted
- Date: 2026-11-16
- Deciders: @yantene

## Context / 背景

記事の本文には、別の記事への内部リンクと脚注の参照がある。どちらも、行き先に何があるかは
飛んでみるまで分からない。脚注は末尾まで飛んで戻ってくることになり、読んでいた場所を見失う。

リンクに触ったところで行き先の中身を小さく出したい (内部リンクは題・要約・公開日、脚注は
注の本文)。決めることは 3 つある。

- **内部リンクの中身をどこから持ってくるか。** リンク先の題と要約は、リンク元の記事の
  MDAST には無い
- **どこに出すか。** リンクの脇に浮かせるには位置合わせが要る。このリポジトリは自前の
  コードで `style` 属性を書かない ([ADR 0007](0007-strict-csp-outside-development.md))
- **誰に出すか。** ホバーできない読み手 (タッチ) と、JavaScript が動かない読み手が居る

制約が 2 つある。記事には読み手に見せない段階 (`draft` など) があり、その題は漏らせない
([ADR 0040](0040-article-status-and-reader-facing-repository.md))。記事ページは h-entry として
読まれるので、本文 (`e-content`) の中身を増やせない。

## 検討した選択肢

### 内部リンクの中身

- **案 A: 触ったときに API へ取りに行く** — `GET /api/v1/articles/<slug>/preview` が
  題・要約・公開日・カバー画像を返す。引くのは `D1ArticleQueryRepository.forReaders`。
  - Pros: リンク先を直せば、次に触ったときから新しい中身が出る。見せてよいかの判定が
    読み取り口 1 か所に畳まれている
  - Cons: 触ってから出るまでに通信が 1 回挟まる
- **案 B: refresh のときに、リンク先の題と要約をリンク元の MDAST に焼き込む** —
  読み手のリクエストは通信しない。
  - Pros: 触った瞬間に出せる
  - Cons: リンク先の題や要約を直しても、リンク元の記事が変わらなければ古いまま残る
    (refresh は変更のあった記事しか処理しない)。焼き込む経路で `forReaders` を通し忘れると、
    下書きの題が公開記事の MDAST に入り、原文と一緒に配られる。入れるときと、焼き込む
    中身を変えるたびに force refresh が要る

### 位置合わせ

- **案 A: Popover API + CSS anchor positioning** — チップは `popover` で最前面に出し、
  位置は CSS が決める。JavaScript が渡すのは「どのリンクを指しているか」の印だけ。
  - Pros: `style` 属性を書かない。スクロールにもリサイズにも、何もしなくても付いてくる
  - Cons: anchor positioning の無いブラウザでは、リンクの脇に出せない
- **案 B: JavaScript で座標を計算して書き込む (floating-ui など)** —
  - Pros: 古いブラウザでもリンクの脇に出る
  - Cons: `top` / `left` を `style` 属性へ書き続けることになる。依存も 1 つ増える

## 決定

**中身は触ったときに取りに行き (案 A)、位置は CSS で決める (案 A)。**

### プレビュー API は読み手向けで固定する

`GET /api/v1/articles/<slug>/preview` は `forReaders(d1).findBySlug` で引く。
**管理者でも分けない。** この応答には公開のキャッシュヘッダを付けるので、管理者に下書きの
題を返すと、同じ URL を引いた読み手にそのまま配られる。誰が引いているか (セッション) を
見に行くこと自体をしない。記事ページ・原文・アセット・記事の JSON API は管理者に下書きを
見せるが ([ADR 0040](0040-article-status-and-reader-facing-repository.md))、ここはその 4 つに
加えない。

`unlisted` は返す。`findBySlug` が通すのは「URL を知っていれば読める」記事で、記事ページも
記事の JSON API も読み手に返している。プレビューが出るのは本文にリンクが張られている
ときなので、URL は既に明かされている。

キャッシュヘッダはアセットや原文と同じ振り分け (`contentCacheControlFor`) に乗せる。
BASIC 認証のある環境では `private` になる。

取った結果はページの中で覚え、同じ記事には 2 回取りに行かない。見えない記事 (404) も
覚える。通信の失敗は覚えない。

### 脚注の中身は、組み終えた木から写す

脚注の本文は同じ記事の MDAST (`footnoteDefinition`) にあるので、通信は要らない。
`footnoteDefinition` を別に組み直すことはせず、**toHast が末尾に起こした脚注一覧を、
変換をすべて終えたあとで写す**。リンクの付け替えも数式も画像の解決も、本文と同じものが
必ず乗る。別に組み直すと、変換を足したときに片方だけ古びる。

写すときに、戻りの矢印と `id` を外す (末尾の一覧と `id` が重複するため)。

### 出し分けは入力手段で行う

| 環境                                 | 内部リンク                  | 脚注の参照                  |
| ------------------------------------ | --------------------------- | --------------------------- |
| `(hover: hover) and (pointer: fine)` | ホバー / フォーカスでチップ | ホバー / フォーカスでチップ |
| それ以外 (タッチ)                    | 素のリンク                  | 押すとドロワー (`<dialog>`) |
| JavaScript が動かない・印刷          | 素のリンク                  | `#fn-1` へ飛ぶ              |

画面の幅では分けない。幅の広いタブレットにもホバーは無い。

入力手段を問うのは**出来事のハンドラの中だけ**で、描き分けには使わない。サーバーは読み手の
入力手段を知らないので、描き分けると hydration で食い違う。

### サーバーは何も足さない

チップもドロワーも、読み手が触ってから `document.body` の下に出す。サーバーが描く HTML に
プレビューの痕は無く、脚注の参照は `#fn-1` へのリンクのまま、末尾の脚注一覧も残る。
本文 (`e-content`) の中に脚注の写しを置かないのは、h-entry として読まれる記事の中身に
同じ文が 2 回入るため。

### 邪魔にならないこと

ホバーで出るものは、読み進めたい人には邪魔になる。

- 出すまで 300ms 待つ。通り過ぎただけのカーソルには出さず、通信もしない
- 離れたら 150ms で閉じる。この猶予は、リンクからチップへカーソルを移すためだけにある
- Esc で閉じる。閉じた相手には、一度離れるまで出し直さない
- チップの中のリンクからは、更にチップを出さない

### anchor positioning の無いブラウザ

チップを画面の下端に固定して出す (`@supports` で分ける)。Popover API も無ければ、
チップは出さず素のリンクのまま振る舞う。

## 帰結 / Consequences

- 良い面: リンク先を直せば、プレビューも次から新しくなる。force refresh は要らない。
  MDAST の形は変わらない。
- 良い面: 下書きの題が漏れる経路が、読み取り口 1 か所に畳まれている。
- 悪い面: 内部リンクのチップは、触ってから出るまでに通信 1 回ぶん遅れる。
- 悪い面: チップは同時に 1 つしか出せない (錨の名前を 1 つしか持たない)。
- 悪い面: ドロワーは指に付いて動かない。追わせるには位置を `style` 属性へ書き続ける
  ことになるので、払ったかどうかを離した時点で決めて閉じるだけにしている。
- 検証方法:
  - `preview.handler.test.ts` — 隠す段階の記事が管理者にも 404 であること、
    セッションを見に行かないこと
  - `mdast-renderer.preview.test.tsx` — サーバーの出力にプレビューの痕が無いこと、
    `style` 属性を書かないこと、遅延と閉じ方
  - `hover-intent.test.ts` — 出すまでの待ちと、閉じるまでの猶予
