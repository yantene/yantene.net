# 0014. リンクカードは OGP だけを見て、取れなければ素のリンクに落とす

- Status: Accepted
- Date: 2026-08-12
- Deciders: @yantene

## Context / 背景

本文に単独行で置かれた URL を、リンク先の見出しと絵を添えたカードとして出したい
([#172](https://github.com/yantene/yantene.net/issues/172))。ここには 3 つの力学がある。

1. **リンク先は自分の管理下に無い。** 落ちていることも、OGP を持っていないことも、
   ある日 HTML の形を変えることもある。どれもこちらから見れば異常ではない。
2. **このサイトは fail-loud を既定にしている。** 設定不備やキャッシュ不整合は静かに
   劣化させず明示的に失敗させる ([ADR 0004](0004-github-as-content-source-of-truth.md))。
   外部サイトへの依存はこの原則と噛み合わない。
3. **CSP が相手のドメインを読み込ませない。** `img-src 'self' data:` かつ
   `frame-src` は YouTube だけ ([ADR 0007](0007-strict-csp-outside-development.md))。
   相手の画像も相手の埋め込み HTML も、そのままでは画面に出せない。

## 検討した選択肢

### 何を見て取るか

- **案 A: 一般的なフェッチチェーン (oEmbed → Open Graph → JSON-LD)** — Slack 等が使う順。
  - Pros: プロバイダが用意した埋め込みをそのまま出せるので、動画やツイートが「本物」で出る。
  - Cons: oEmbed が返すのはプロバイダの埋め込み HTML で、多くは iframe。採用すると
    相手が増えるたびに `frame-src` を広げることになる。カードの見た目も相手任せになり、
    本文の組版と揃わない。
- **案 B: Open Graph だけを見る** — `og:title` / `og:description` / `og:image` /
  `og:site_name` と favicon。無ければ `<title>` で代える。
  - Pros: 欲しいのは題・説明・絵・出どころだけで、それは OGP で足りる。マークアップを
    自分で持てるので本文と同じ組版に載せられ、CSP を広げずに済む。
  - Cons: 埋め込みとしての機能 (再生・展開) は得られない。OGP を出していないサイトは
    カードにならない。

### 取れなかったときにどうするか

- **案 A: fail-loud。** 取得に失敗したら refresh を失敗させる。
  - Pros: 既定の原則と揃う。壊れていることが即座に分かる。
  - Cons: **相手のサイトの一時的な不調で、こちらのコンテンツ同期が止まる。**
    リンク 1 本のために記事の公開が滞るのは釣り合わない。
- **案 B: 素のリンクとして描く。** カードにできなかったことを記録して先へ進む。
  - Pros: 記事は常に読める。カードは「あれば嬉しいもの」という位置づけになる。
  - Cons: fail-loud の例外を 1 つ作ることになる。どこまでが例外かを明示しないと、
    「外部依存だから」を口実に他所へ広がる。

### 一度取れたものが取れなくなったとき

- **案 A: すぐ素のリンクに落とす。**
  - Pros: 単純。出ているものは必ず最新。
  - Cons: 相手が数分落ちただけで記事の見た目が変わる。読み手には理由が分からない。
- **案 B: 前回の中身を出し続ける。**
  - Pros: 記事の見た目が安定する。
  - Cons: 相手が畳んだあとも古い中身を永久に出す。回収する手立てが無い。
- **案 C: 上限を決めて持ちこたえる。**
  - Pros: 短い不調を吸収しつつ、恒久的な消失はいつか回収される。
  - Cons: 状態が 1 つ増える。「いま出ているカードが古いかもしれない」時間帯ができる。

## 決定

**OGP だけを見て、取れなければ素のリンクとして描く。ただし一度取れたものは、
上限つきで前回の中身を持ちこたえる。**

線引きはこうする。**fail-loud は自分の管理下にあるものに適用する。** 設定・D1・R2・
コンテンツ正本の不整合は、それらしく動き続けさせずに落とす。一方、**外部サイトの応答は
入力であって、こちらの状態ではない。** 取れないことは想定内なので、記録を残して
先へ進む。この例外は `ILinkCardFetcher` の実装 (`OgpLinkCardFetcher`) の中だけに閉じ、
そこから外へは「取れた／取れなかった」しか出さない。

### カードの持ち方

- **カードは記事ではなく URL に紐づける。** 同じリンクを複数の記事から張っても取得は
  1 回で済む。どの記事に出るかは、その記事の MDAST を見れば分かる。
- **画像は R2 に写して自分のところから配る。** `img-src 'self' data:` なので相手の
  ドメインからは読めない。配信パスは URL の SHA-256 (`/api/v1/link-cards/<id>/image`)
  で、相手の URL を露出させない。**SVG は写さない** — `<img>` で描く限りスクリプトは
  動かないが、写した先は自分のオリジンなので、配信 URL を直接開かれると自分のオリジンで
  実行されうる。
- **取れなかったことも行として残す。** 行を作らずにおくと、落ちている相手を refresh の
  たびに叩き直すことになる。成否と時刻を覚えておけば、次にいつ試すかをこちらで決められる。
- **カード化の判定は 1 か所に置く** (`app/lib/link-card/bare-link.ts`)。取得側 (refresh)
  と描画側 (MdastRenderer) が別々に判定すると、片方だけカードになる食い違いが静かに起きる。
  リスト項目と脚注の中は対象外にする (どちらも参照の列挙で、カードが挟まると並びが読めなくなる)。

### 絵は 3 通りの状態で持つ

絵の無いカードと、絵を取り逃したカードは、出来上がりが同じで見分けが付かない。
`stored` / `absent` / `missed` の 3 通りで区別する。

- **`missed` にするのは、`og:image` を取りに行って応答が得られなかったときだけ。**
  レート制限・不調・時間切れ・大きすぎがこれに当たる。**載せられない型 (SVG など) は
  `absent`。** 取り直しても結論が変わらないため。
- **favicon の取り逃しは数えない。** `rel=icon` が書かれていない相手には慣例の
  `/favicon.ico` を試すので、置いていないサイトでは毎回取れない。これを取り逃しに
  数えると、そういう相手のカードが短い期限で永久に回り続ける。
- **取り逃したことは info で残す。** 無音だと、絵の欠けたカードを見ても原因を追えない。
- **D1 は `has_image` と `image_missed` の 2 列で持つ。** 3 通りに畳むのは infra の
  仕事で、ドメインは 1 つの状態として扱う。両方立った行は書かない。
- **取り逃したときは前回の写しを捨てる。** 絵は次に取れるまで出ない。写しを残して
  「絵はある」ことにし続けると、相手が絵を差し替えたときに古い絵を出し続けることになり、
  それは取り逃しより静かな壊れ方だから。
- **短い間隔で試し続けるのは 3 日まで。** 越えたら取れているカードと同じ 14 日に倒す。
  上限が無いと、恒久的に壊れた相手 (0 バイトを返す CDN、hotlink 保護) を毎日叩き続け、
  1 回の refresh の枠 (40) を食って**本当に古びたカードを `deferred` へ押し出す**。
  **諦めて `absent` にはしない。** 絵が無いと分かったわけではないので、状態としては
  嘘になる。変えるのは試す間隔だけ。起点は `image_missed_since` に持ち、取り逃している
  間は動かさない (`fetched_at` だけが進む)。両方を進めると上限にいつまでも届かない。

### 取れなくなったカードは 3 日だけ持ちこたえる

- **持ちこたえるのは中身が丸ごと。** 題・説明・絵の写しをまとめて残す。題だけ残して絵を
  消すと、相手が一瞬落ちただけでカードの形が変わる。**どうせ古いものを見せているので、
  古さの単位を揃えるほうが読み手にとって一貫している。**
- **上限は失敗の起点から 3 日。** 越えてもなお失敗したら中身を捨て、素のリンクに戻す。
  相手の不調が 3 日続くなら、それはもう「一時的」ではない。
- **これは壁時計の保証ではない。** 判定されるのは「3 日を越えてから、次に取りに行って
  失敗したとき」でしかない。refresh はコンテンツの push で走るので、push が来なければ
  3 日は 3 週間にもなる。**上限は「いつか必ず回収される」ことの保証であって、
  「3 日で消える」ことの保証ではない。**
- したがって**諦めるまでの試行は多くとも 3 回**で、下限は 1 回。24 時間の刻みで
  refresh が来続けたときに 3 回になる。**「3 回は試す」ではないことに注意。**
- **列は `fetch_failed_since` (時刻・NULL 可) で持つ。** 真偽値では上限を測れない。
  失敗が続く間この列は動かさず、`fetched_at` だけが進む。両方を進めると上限に永久に届かない。
- **NULL でない行は必ず中身を持つ。** 中身の無い行 (title が NULL) は持ちこたえるものが
  無いので常に NULL。この対応のおかげで、2 つの列の組が 3 つの状態に 1 対 1 で対応し、
  行からエンティティへの変換に「ありえない組」が残らない。
- **持ちこたえた URL は refresh の結果に `kept` として出す。** `failed` に混ぜない。
  混ぜると、運用者が「素のリンクに落ちた」のか「カードのまま古い中身が出ている」のかを
  見分けられない。**この 2 つは見た目の壊れ方が違う。**

絵と中身で扱いが逆なのは意図的である。**絵だけ取れないときはページが生きているので、
相手が絵を差し替えた可能性を観測できる。ページごと取れないときは何が起きたか分からない。**
観測できるときは古いものを出さず、観測できないときは持ちこたえる。

### 期限は 3 段

refresh の変更検出は Markdown とアセットのハッシュなので、記事が変わらない限りカードは
取り直されない。カード自身に期限を持たせ、期限切れの行を refresh のついでに洗い替える。

| 状態                                | 古いとみなすまで |
| ----------------------------------- | ---------------- |
| 取れた (絵も含めて揃っている)       | 14 日            |
| 絵を取り逃した (`missed`)・3 日以内 | 24 時間          |
| 絵を取り逃した (`missed`)・3 日超   | 14 日            |
| 取れなかった                        | 24 時間          |

期限切れの抽出は記事ではなくカードの表から引くので、変更のなかった記事の MDAST を
読み直さずに済む。

**期限の境目は 3 つともドメインが決めて渡す** (`staleCutoffs`)。いまの値が同じでも
項目は分ける。片方だけ変えたときに SQL とエンティティが黙って食い違うため。
SQL の 3 つの枝は重ならないように書く。重ねると、期限の大小を変えたときに黙って
長いほうが効く。

## 帰結 / Consequences

- 良い面
  - 相手のサイトが落ちていても、記事の同期も表示も止まらない。短い不調では見た目も変わらない。
  - `frame-src` を広げずに済み、カードの組版を本文と揃えられる。
  - 取得は refresh のときだけで、読み手のリクエストは外部に触れない (ADR 0004)。
  - レート制限のような一時的な失敗から、次の refresh で戻る。
- 悪い面・トレードオフ
  - OGP を出していないサイトはカードにならない。素のリンクのままになる。
  - リンク先の変化への追随は最大 14 日遅れる。急ぐときは force refresh を流す。
  - **「いま出ているカードが古いかもしれない」時間帯ができる。** 出ている間、消す手立ては
    無い (force refresh も同じ失敗の経路を通る)。急ぐなら D1 の行を直接消すことになる。
  - **行を消しても R2 の写しは残る。** 掃除は同期の経路でしか走らないので、絵と favicon は
    `link-cards/<id>/` に置き去りになる。
  - **`og:image` が恒久的に 404 の相手も、3 日を過ぎれば 14 日間隔に落ちる。**
    それまでの 3 日ぶんは叩きに行く。
  - fail-loud の例外を 1 つ作った。**この例外は「外部サイトの応答」に限る。** 自分の
    ストレージや設定の不整合をここに紛れ込ませないこと。
  - 1 回の refresh で取りに行く枚数に上限 (40 枚) がある。溢れた分は次回に回り、
    件数は結果に `deferred` として出す (黙って切り捨てない)。
- 検証方法 / 今後の宣言
  - `OgpLinkCardFetcher` の失敗系はテストで固定してある (取りに行けない・HTML でない・
    題が無い・大きすぎる・SVG)。いずれも throw せず undefined を返すこと。
  - 期限の刻みは `link-card.entity.test.ts`、SQL の枝は `link-card.repository.test.ts`、
    取り逃しの判定と記録は `ogp-link-card-fetcher.test.ts`、状態の受け渡しは
    `link-cards-refresh.service.test.ts` で固定してある。
  - カード化の判定 (`bare-link.test.ts`) と描画 (`mdast-renderer.link-card.test.tsx`) は
    同じ入力で同じ結論になることを両側から押さえている。
  - **状態を増やすときはここに書いた線引きを読み直すこと。** 相手の応答の形をカードの
    状態に写し取り始めると際限が無い。
  - この機能を入れた後、**既存ノートにカードを行き渡らせるには一度 force refresh が要る**
    (通常の refresh は変更のあった記事しか見ないため)。
