# 0014. リンクカードは OGP だけを見て、取れなければ素のリンクに落とす

- Status: Accepted (期限の刻みのみ [0025](0025-retry-link-cards-that-missed-their-image.md) で置き換え)
- Date: 2026-08-12
- Deciders: @yantene

> ⚠️ **カードの期限については [ADR 0025](0025-retry-link-cards-that-missed-their-image.md) を参照。**
> 絵だけ取り逃したカードを別の状態として持ち、そこだけ 1 日で取り直すようにした。
> 以下の「取れたものは 14 日、取れなかったものは 1 日」の 2 段は、3 段になっている。
> **OGP だけを見る判断と、取れなければ素のリンクに落とす判断は変わらない。**

## Context / 背景

本文に単独行で置かれた URL を、リンク先の見出しと絵を添えたカードとして出したい
([#172](https://github.com/yantene/yantene.net/issues/172))。ここには 3 つの力学がある。

1. **リンク先は自分の管理下に無い。** 落ちていることも、OGP を持っていないことも、
   ある日 HTML の形を変えることもある。どれもこちらから見れば異常ではない。
2. **このサイトは fail-loud を既定にしている。** 設定不備やキャッシュ不整合は静かに
   劣化させず明示的に失敗させる ([ADR 0004](0004-github-as-content-source-of-truth.md))。
   外部サイトへの依存はこの原則と噛み合わない。
3. **CSP が相手のドメインを読み込ませない。** `img-src 'self' data:` かつ
   `frame-src` は YouTube だけ ([ADR 0007](0007-strict-csp-outside-development.md))。
   相手の画像も相手の埋め込み HTML も、そのままでは画面に出せない。

## 検討した選択肢

### 何を見て取るか

- **案 A: 一般的なフェッチチェーン (oEmbed → Open Graph → JSON-LD)** — Slack 等が使う順。
  - Pros: プロバイダが用意した埋め込みをそのまま出せるので、動画やツイートが「本物」で出る。
  - Cons: oEmbed が返すのはプロバイダの埋め込み HTML で、多くは iframe。採用すると
    相手が増えるたびに `frame-src` を広げることになる。カードの見た目も相手任せになり、
    本文の組版と揃わない。
- **案 B: Open Graph だけを見る** — `og:title` / `og:description` / `og:image` /
  `og:site_name` と favicon。無ければ `<title>` で代える。
  - Pros: 欲しいのは題・説明・絵・出どころだけで、それは OGP で足りる。マークアップを
    自分で持てるので本文と同じ組版に載せられ、CSP を広げずに済む。
  - Cons: 埋め込みとしての機能 (再生・展開) は得られない。OGP を出していないサイトは
    カードにならない。

### 取れなかったときにどうするか

- **案 A: fail-loud。** 取得に失敗したら refresh を失敗させる。
  - Pros: 既定の原則と揃う。壊れていることが即座に分かる。
  - Cons: **相手のサイトの一時的な不調で、こちらのコンテンツ同期が止まる。**
    リンク 1 本のために記事の公開が滞るのは釣り合わない。
- **案 B: 素のリンクとして描く。** カードにできなかったことを記録して先へ進む。
  - Pros: 記事は常に読める。カードは「あれば嬉しいもの」という位置づけになる。
  - Cons: fail-loud の例外を 1 つ作ることになる。どこまでが例外かを明示しないと、
    「外部依存だから」を口実に他所へ広がる。

## 決定

**案 B をどちらも採る。OGP だけを見て、取れなければ素のリンクとして描く。**

線引きはこうする。**fail-loud は自分の管理下にあるものに適用する。** 設定・D1・R2・
コンテンツ正本の不整合は、それらしく動き続けさせずに落とす。一方、**外部サイトの応答は
入力であって、こちらの状態ではない。** 取れないことは想定内なので、記録を残して
先へ進む。この例外は `ILinkCardFetcher` の実装 (`OgpLinkCardFetcher`) の中だけに閉じ、
そこから外へは「取れた／取れなかった」しか出さない。

付随して決めたこと。

- **カードは記事ではなく URL に紐づける。** 同じリンクを複数の記事から張っても取得は
  1 回で済む。どの記事に出るかは、その記事の MDAST を見れば分かる。
- **画像は R2 に写して自分のところから配る。** `img-src 'self' data:` なので相手の
  ドメインからは読めない。配信パスは URL の SHA-256 (`/api/v1/link-cards/<id>/image`)
  で、相手の URL を露出させない。**SVG は写さない** — `<img>` で描く限りスクリプトは
  動かないが、写した先は自分のオリジンなので、配信 URL を直接開かれると自分のオリジンで
  実行されうる。
- **取れなかったことも行として残す。** 行を作らずにおくと、落ちている相手を refresh の
  たびに叩き直すことになる。成否と時刻を覚えておけば、次にいつ試すかをこちらで決められる。
- **カードに期限を持たせる。** refresh の変更検出は Markdown とアセットのハッシュなので、
  記事が変わらない限りカードは取り直されない。取れたものは 14 日、取れなかったものは
  1 日で古いとみなし、期限切れの行を refresh のついでに洗い替える。期限切れの抽出は
  記事ではなくカードの表から引くので、変更のなかった記事の MDAST を読み直さずに済む。
- **カード化の判定は 1 か所に置く** (`app/lib/link-card/bare-link.ts`)。取得側 (refresh)
  と描画側 (MdastRenderer) が別々に判定すると、片方だけカードになる食い違いが静かに起きる。
  リスト項目と脚注の中は対象外にする (どちらも参照の列挙で、カードが挟まると並びが読めなくなる)。

## 帰結 / Consequences

- 良い面
  - 相手のサイトが落ちていても、記事の同期も表示も止まらない。
  - `frame-src` を広げずに済み、カードの組版を本文と揃えられる。
  - 取得は refresh のときだけで、読み手のリクエストは外部に触れない (ADR 0004)。
- 悪い面・トレードオフ
  - OGP を出していないサイトはカードにならない。素のリンクのままになる。
  - リンク先の変化への追随は最大 14 日遅れる。急ぐときは force refresh を流す。
  - fail-loud の例外を 1 つ作った。**この例外は「外部サイトの応答」に限る。** 自分の
    ストレージや設定の不整合をここに紛れ込ませないこと。
  - 1 回の refresh で取りに行く枚数に上限 (40 枚) がある。溢れた分は次回に回り、
    件数は結果に `deferred` として出す (黙って切り捨てない)。
- 検証方法 / 今後の宣言
  - `OgpLinkCardFetcher` の失敗系はテストで固定してある (取りに行けない・HTML でない・
    題が無い・大きすぎる・SVG)。いずれも throw せず undefined を返すこと。
  - カード化の判定 (`bare-link.test.ts`) と描画 (`mdast-renderer.link-card.test.tsx`) は
    同じ入力で同じ結論になることを両側から押さえている。
  - この機能を入れた後、**既存ノートにカードを行き渡らせるには一度 force refresh が要る**
    (通常の refresh は変更のあった記事しか見ないため)。
