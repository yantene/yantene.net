# 0045. 経歴を `/about` の名乗りの直下に、章ごとに畳んで出す

- Status: Accepted
- Date: 2026-09-27
- Deciders: @yantene

## Context / 背景

`/about` は、名乗り (`ProfileCard`: 顔・名前・短い自己紹介)・長い自己紹介の本文・作ったもの・
経歴の 4 つの節でできている。経歴の中身と束ね方 (フロントマターの `history`、章で束ねる、
日は 3 段の精度、並べ直さない) は [ADR 0044](0044-show-the-history-as-a-timeline-of-chapters.md)
が決めている。この ADR が決めるのは、その節を**ページのどこに、どういう姿で置くか**である。

置き場所には [ADR 0041](0041-keep-the-profile-in-the-content-repository.md) 以来の懸念が
掛かっている。個人サイトの `/about` に学歴や資格を並べると、**読み手が最初に受け取るのが
履歴書になる**。

経歴は生まれたところ (`誕生`) から始まり、小学校・中学校・高校・大学・社会人と章が続く。
入学と卒業のあいだに「HTML と出会う」「Ubuntu 8.04 と出会う」が挟まり、社会人の章には
引っ越しと結婚が並ぶ。学歴と資格の一覧ではなく、書き手がどう育ってきたかの年表になっている。
そのぶん長く、全部を開いたまま頭に置くと、本文が 30 行近く下へ押される。

## 検討した選択肢

置き場所について。

- **案 A: ページの末尾 (作ったものの後)**
  - Pros: 名乗りの近くに学歴が来ないので、履歴書に見える余地が最も小さい。
  - Cons: 自分史は頭から読むものなのに、本文を読み終えた人しか辿り着かない。本文には
    「保育園のころ」「小学 4 年生のとき」といった話があり、年表を先に見ておくほうが
    それらの時期が掴みやすい。
- **案 B: 名乗りの直下 (本文の前)**
  - Pros: 名乗りで誰かを知り、年表でどう育ってきたかを知り、本文で何が好きかを読む、の
    順になる。
  - Cons: 全部を開いて置くと本文が押される。入学と卒業が並ぶので、履歴書にも見える。
- **案 C: 名乗りより上 (ページの頭)**
  - Pros: 年表が最も目に入る。
  - Cons: ページを開いて最初に見えるのが顔と名前ではなく年表になる。名乗りはトップ・
    記事の末尾・`/about` の 3 か所で同じ形をしており、`/about` だけ頭が変わる。

畳み方について。

- **案 D: 章ごと畳み、名前だけを見せる**
  - Pros: 短い。
  - Cons: 畳んだ姿から中身が何も分からない。「小学校」「中学校」の並びは、それ自体が
    学歴の一覧になる。
- **案 E: 章ごと畳み、書き手が選んだ出来事だけを見せる**
  - Pros: 畳んだ姿が「この人の要所」になる。選ぶのは書き手なので、入学と卒業ではなく
    「HTML と出会う」を残せる。
  - Cons: フロントマターに欄が 1 つ増える。

## 決定

**案 B と案 E。** 経歴の節は `/about` の名乗りの直下に置き、長い自己紹介の本文と作ったものは
その後に続く。**章は畳んだ姿で出し**、畳んでいる間は `important: true` の付いた出来事だけを
出す。

```yaml
history:
  - chapter: 小学校
    entries:
      - date: 2000-04-06
        text: 小学校入学
      - date: 2004
        text: HTML と出会う
        important: true
```

- **省いたところには `⋮` を立てる。** 重要でない出来事が続く束の頭ごとに 1 つ。縦線は
  そこで点々に変わる。束を 1 つにまとめると、どこを省いたのかが分からない
- **重要な出来事を 1 つも持たない章は、`⋮` だけになる。** 章を消しはしない。章の並びは
  書き手の語りなので、畳んでも欠けさせない
- **開くのは章ごと。** 章の名前を押すとその章の全部が出る。器は `<details>` で、
  JavaScript が無くても開く。開いているかどうかだけを `<details>` が持ち、どの出来事を
  隠すかは CSS (`:has([open])`) が決める。出来事の列を `<details>` の中に入れると、
  畳んだ間は重要な出来事まで隠れてしまうため
- **畳んだ状態を覚えない。** ページを開き直せば畳んだ姿に戻る。覚えるには cookie か
  ストレージが要り、SSR とクライアントで姿が食い違う

0041 の懸念を押さえるのは、次の 3 つである。

- **名乗りより上にも、その中にも出さない。** ページの頭にあるのは顔・名前・短い自己紹介の
  まま
- **経歴は生まれたところから書く。** 頭に置いてよいのは、年表が学歴と資格の一覧ではなく
  自分史として読めるからである。これはコードでは止められない書き手の規範で、
  `content/AGENTS.md` の側に書く
- **畳んだ姿に出すものは書き手が選ぶ。** 入学と卒業は、開かないと並ばない

束ね方 (章で束ねる、並べ直さない) と、h-card にも JSON-LD にも出さないことは 0044 のまま
変わらない。`important` も機械が読む形 (microformats の印・`time` 要素) には載せない。

**保存は `profile_history.important` の 1 列。** 書かなければ false。真偽値以外 (`yes` や
`"true"`) は読めない値としてプロフィールごとスキップする。字によって畳んだ章に出たり
出なかったりするのを避けるため。列は `NOT NULL DEFAULT false` で足してあり、この列を
知らないコードが書き込んでも落ちない。

## 帰結 / Consequences

- 良い面: 本文に出てくる時期の話を、先に年表で掴んでから読める。畳んであるので、本文は
  大きくは押されない。
- 悪い面・トレードオフ: どれに `important` を付けるかで、畳んだ姿が履歴書にも自分史にも
  なる。機械が守れるのは節の並びと畳んだ既定だけで、中身は書き手に掛かっている。
- 悪い面: ページ内検索は畳んだ出来事を拾わない。
- 悪い面: 経歴 1 行のバインドパラメータが 13 個になり、D1 の上限 (100) に収めるために
  1 文あたり 7 行で切っている。
- 検証方法:
  - `about.placement.test.tsx` が節の並び (名乗り → 経歴 → 本文 → 作ったもの) を固定する。
    **置き場所は見た目に出ない** — どの順に並べても「それらしく」出てしまうので、人の目
    では守れない。
  - `profile-history.mf2.test.tsx` が、章が `open` なしで描かれることと、`⋮` が省いた束
    ごとに立つことを見る。
  - `profile-refresh.service.test.ts` が、真偽値でない `important` をスキップとして返す
    ことを固定する。
  - `profile.command-repository.test.ts` の「D1 のバインドパラメータ上限」が、列を足した
    ときに 1 文あたりの行数の見直しを迫る。
