# 0045. 経歴を `/about` の名乗りの直下に出す

- Status: Accepted
- Date: 2026-09-27
- Deciders: @yantene

## Context / 背景

`/about` は、名乗り (`ProfileCard`: 顔・名前・短い自己紹介)・長い自己紹介の本文・作ったもの・
経歴の 4 つの節でできている。経歴の中身と束ね方 (フロントマターの `history`、章で束ねる、
日は 3 段の精度、並べ直さない) は [ADR 0044](0044-show-the-history-as-a-timeline-of-chapters.md)
が決めている。この ADR が決めるのは、その節を**ページのどこに置くか**だけである。

置き場所には [ADR 0041](0041-keep-the-profile-in-the-content-repository.md) 以来の懸念が
掛かっている。個人サイトの `/about` に学歴や資格を並べると、**読み手が最初に受け取るのが
履歴書になる**。

経歴は生まれたところ (`誕生`) から始まり、小学校・中学校・高校・大学・社会人と章が続く。
入学と卒業のあいだに「HTML と出会う」「Ubuntu 8.04 と出会う」が挟まり、社会人の章には
引っ越しと結婚が並ぶ。学歴と資格の一覧ではなく、書き手がどう育ってきたかの年表になっている。

## 検討した選択肢

- **案 A: ページの末尾 (作ったものの後)**
  - Pros: 名乗りの近くに学歴が来ないので、履歴書に見える余地が最も小さい。
  - Cons: 自分史は頭から読むものなのに、本文を読み終えた人しか辿り着かない。本文には
    「保育園のころ」「小学 4 年生のとき」といった話があり、年表を先に見ておくほうが
    それらの時期が掴みやすい。
- **案 B: 名乗りの直下 (本文の前)**
  - Pros: 名乗りで誰かを知り、年表でどう育ってきたかを知り、本文で何が好きかを読む、の
    順になる。
  - Cons: 年表の書き方が学歴の一覧に寄ると、0041 の懸念がそのまま表に出る。
- **案 C: 名乗りより上 (ページの頭)**
  - Pros: 年表が最も目に入る。
  - Cons: ページを開いて最初に見えるのが顔と名前ではなく年表になる。名乗りはトップ・
    記事の末尾・`/about` の 3 か所で同じ形をしており、`/about` だけ頭が変わる。

## 決定

**案 B。** 経歴の節は `/about` の名乗りの直下に置き、長い自己紹介の本文と作ったものは
その後に続く。

0041 の懸念を押さえるのは、次の 2 つである。

- **名乗りより上にも、その中にも出さない。** ページの頭にあるのは顔・名前・短い自己紹介の
  まま
- **経歴は生まれたところから書く。** 頭に置いてよいのは、年表が学歴と資格の一覧ではなく
  自分史として読めるからである。高校から始まる書き方に戻すと、名乗りの次に読み手が
  受け取るのは履歴書になる。こちらはコードでは止められない書き手の規範で、
  `content/AGENTS.md` の側に書く

束ね方 (章で束ねる、並べ直さない) と、h-card にも JSON-LD にも出さないことは 0044 のまま
変わらない。

## 帰結 / Consequences

- 良い面: 本文に出てくる時期の話を、先に年表で掴んでから読める。
- 悪い面・トレードオフ: 経歴の書き方しだいで履歴書に見える。機械が守れるのは節の並び
  だけで、中身が自分史になっているかは書き手に掛かっている。
- 悪い面: 経歴が長くなるほど、本文が下へ押される。
- 検証方法:
  - `about.placement.test.tsx` が節の並び (名乗り → 経歴 → 本文 → 作ったもの) を固定する。
    **置き場所は見た目に出ない** — どの順に並べても「それらしく」出てしまうので、人の目
    では守れない。
